# مِيقَات — مواقيت الصلاة | وثيقة المتطلبات الأولية
الحالة: مسودة تأسيسية — 06/11/2026.

## الهدف
تطبيق خفيف لـUbuntu يُظهر اسم الصلاة التالية والعدّ التنازلي إليها في شريط GNOME Shell العلوي؛ تُعرض تفاصيل الصلاة والمنطقة وزاوية القبلة والتاريخ الهجري عند مرور المؤشر، وتفتح مواقيت اليوم والإعدادات بالنقر. يعمل دون نافذة دائمة ودون اتصال مستمر.

## متطلبات واجهة الاستخدام
1. **الشريط العلوي**: صيغة قابلة للضبط مثل «الظهر · 00:18:42»، بلغة عربية صحيحة واتجاه RTL قابل للقراءة. تجديد العدّ التنازلي بانتظام، مع خيار الدقة (ثانية أو دقيقة).
2. **Hover**: بطاقة موجزة لا تعيق الشريط وتُغلق عند مغادرة المؤشر؛ اسم الصلاة، وقتها، اسم المدينة/الدولة، زاويتا القبلة بالترتيب: المغناطيسية أولًا ثم الجغرافية، التاريخ الهجري، والمصدر. إذا لم تدعم نسخة GNOME السلوك المباشر بأمان، يُقدَّم بديل موثق مع الحفاظ على النقر.
3. **Click**: قائمة مواقيت اليوم (الفجر، الشروق، الظهر، العصر، المغرب، العشاء) مع الوصول إلى نافذة التطبيق الكاملة والإعدادات. لاحقًا يمكن جعل النقر يفتح النافذة مباشرة حسب تفضيل المستخدم.
4. **النافذة الكاملة**: مواقيت اليوم والشهر، الموقع المصرّح به، المصدر، القبلة المرسومة، التاريخ الهجري، حالة مزامنة البيانات، إعدادات العرض واللغة والساعة.
5. **الشروق**: يُعرض في الجدول لكنه ليس صلاة ضمن العدّ التنازلي الافتراضي. بعد العشاء ينتقل العدّ إلى فجر اليوم التالي.
6. **الفصل بين الأذان والوقت**: التنبيه أو تشغيل الصوت وظيفة اختيارية لاحقة؛ لا تُفترض في النسخة الأساسية.
7. **قابلية الوصول**: نصوص واضحة، لوحة مفاتيح، تباين مناسب، رسائل دقيقة عند غياب البيانات.

## أولوية مصدر مواقيت الصلاة
- **الجزائر**: اليومية الرسمية المنشورة من وزارة الشؤون الدينية والأوقاف، بما فيها الجداول المرجعية وفروق المدن وفق الصلاة واليوم/الشهر. لا تسمى نتيجة خوارزمية حسابية «موعدًا رسميًا».
- **الدول المسلمة الأخرى**: المصدر الوطني الرسمي الموثّق إن كان متاحًا للمدينة والفترة، أو طريقة الحساب المعتمدة مع تصنيفها الصحيح. لا نفترض أن لكل دولة رزنامة وطنية واحدة.
- **الدول غير المسلمة**: طريقة دولية محددة بوضوح؛ تكون جهة إسلامية محلية اختيارًا مستقبليًا إن وُجد جدول موثوق.
- **الاستثناء**: عند غياب جدول رسمي ساري، لا تعرض بيانات قديمة كأنها سارية. إن اختار المستخدم الاحتياط الحسابي، يُوسم «محسوب/تقديري» مع اسمه وإعداداته.
- **إتاحة دون اتصال**: احتفاظ بجدول محلي مُرخّص وموثّق للمكان والتواريخ المتاحة؛ عدم استدعاء الويب عند كل تحديث للعدّاد.

## بيانات كل سجل مواقيت
اسم الدولة والمدينة + معرف المكان + المنطقة الزمنية IANA + التاريخ المدني المحلي + مواقيت الفجر والشروق والظهر والعصر والمغرب والعشاء + معرف المصدر ونوعه (official-timetable / authority-method / international-calculation) + مرجع المنشور/الرابط + إصدار الرزنامة + تاريخ الجلب/المراجعة + حالة التحقق + طريقة الحساب/التعديل إن لزم. افصل البيانات المؤكدة عن التوقعات.

## التاريخ الهجري
- الاستفادة من منطق `scientifica007/Hidjri_Calendar` بعد التدقيق، لا نسخ واجهته أو بيانات المواعيد الشخصية.
- تمييز موثق رسميًا/منقول/تقديري؛ تصحيحات ربط بدايات الأشهر بالدولة، مع عرض مصدر التصحيح.
- التفريق بين التاريخ المدني المستخدم للعرض والاعتبار الشرعي لليوم الهجري بعد المغرب؛ إعداد متاح للمستخدم لاحقًا.

## القبلة — متطلبات M2 فقط
- عرض **الزاوية المغناطيسية أولًا** ثم **الزاوية الجغرافية ثانيًا**، مع تسمية مرجع كل زاوية ووحدتها (درجة باتجاه عقارب الساعة من الشمال المعني).
- حساب الزاوية الجغرافية B_true بمسار الدائرة العظمى نحو الكعبة من إحداثيات WGS84 موثقة، ثم `B_magnetic = normalize360(B_true - D)`؛ الانحراف D موجب شرقًا وسالب غربًا. مثال اختبار: جغرافية 100° وانحراف +5° يعطي مغناطيسية 95°؛ وانحراف -5° يعطي 105°.
- اعتماد **WMM2025** للتواريخ من 2025.0 إلى ما قبل 2030.0، أي حتى نهاية 2029، وفق NOAA/NCEI وBGS. اختيار الإصدار بحسب تاريخ الحساب؛ لا تمديد صامت لصلاحية المعاملات. ما بعد الصلاحية يتطلب إصدار WMM مناسبًا موثقًا؛ وإلا تعرض المغناطيسية «غير متاحة» مع سبب واضح، وتبقى الجغرافية متاحة إن صلحت مدخلاتها.
- مدخلات الانحراف: خط العرض والطول الجيوديسيان، الارتفاع بمرجع ووحدات يطلبهما النموذج، والتاريخ كسنة عشرية. توثيق مصدر الإحداثيات والارتفاع ودقتهما وأي ارتفاع افتراضي؛ لا تخمين صامت.
- إظهار إصدار النموذج وتاريخ الحساب والانحراف واتجاهه وصلاحيته. احترام تحذيرات مناطق ضعف المركبة الأفقية/الأقطاب وحدود النموذج؛ لا عرض اتجاه مغناطيسي موثوق إذا كان غير معرّف أو في منطقة الحجب.
- الحساب محلي وخارج tick الواجهة؛ يعاد عند تغير المكان/التاريخ المناسب، ولا حاجة لشبكة لتحديث العدّاد. لا مستشعر مفترض ولا ادعاء توجيه حي للحاسوب أو تصحيح التشويش المغناطيسي المحلي.
- قبول M2 مشروط بمطابقة قيم الاختبار الرسمية لـWMM، واختبارات إشارة الانحراف والتطبيع وعبور السنة وانتهاء الصلاحية والمواقع غير الصالحة/القطبية وحالات القبلة الهندسية غير المعرّفة (عند الكعبة ونقيضها). تدقيق تراخيص المعاملات والمكتبة ومصدرهما قبل أي نسخ. لا تنفيذ لهذه المتطلبات ضمن M0.
- المراجع الأولية (راجعت في 2026-11-06): [NOAA WMM وإصداره وصلاحيته](https://www.ncei.noaa.gov/products/world-magnetic-model)، [تعريف التحويل بين المرجعين](https://www.ncei.noaa.gov/products/geomagnetism-frequently-asked-questions)، [حدود النموذج](https://www.ncei.noaa.gov/products/world-magnetic-model/accuracy-limitations-error-model).

## موثوقية التشغيل
- العمل على Ubuntu 24.04 مع GNOME Shell 46 كهدف مبدئي؛ التحقق محليًا من `gnome-shell --version`.
- لا يجب فتح نافذة التطبيق لتشغيل المؤشر؛ عند تعطيل الإضافة تُلغى جميع المؤقتات والإشارات المضافة.
- بعد السبات، أو تغيير ساعة النظام أو المنطقة الزمنية، يُعاد تحديد الصلاة التالية.
- المعالجة الصحيحة لعبور منتصف الليل والتوقيت الصيفي والتغير بين الدول؛ الاعتماد على المناطق الزمنية IANA وليس فرق UTC ثابت.
- لا اتصال شبكي إجباري أثناء العدّ التنازلي. لا تجميد لواجهة GNOME بسبب طلبات الشبكة أو قراءة ملفات كبيرة.
- عدم تعديل `Hidjri_Calendar` أو `AppHub` في المراحل الأولى.

## معيار قبول أول نموذج (M0)

تحديث 2026-11-06: تجربة المستخدم الأساسية ناجحة، ودورات التفعيل الحقيقية 10/10 ناجحة دون رسائل Shell جديدة؛ اعتمد المستخدم M0 وظيفيًا بعد تأكيد مؤشر واحد وعدّاد طبيعي وعدم وجود بقايا واستقرار سطح المكتب. [تفاصيل الأدلة والقيود](M0_FIELD_ACCEPTANCE_AR.md).
- مؤشر نصي فوق شريط GNOME في بيئة اختبار محلية، يعمل بأوقات **تجريبية معلّمة بوضوح**.
- تحديث العداد وانتقال الصلاة التالية بشكل صحيح، بما في ذلك العشاء → الفجر.
- قائمة بالنقر وبطاقة مرور الفأرة أو بديل قابل للاختبار إذا كان hover يتعارض مع سلوك المؤشر.
- تفعيل وتعطيل الإضافة دون بقايا مؤقتات أو أخطاء في سجلات GNOME.
- اختبارات وحدة للعدّاد وحدود اليوم، مع خطوات إعادة إنتاج واضحة.
- لا يُعتبر المشروع جاهزًا للعبادات حتى تمرّ المواقيت الحقيقية باختبارات مطابقة مستقلة للمصدر الرسمي.
